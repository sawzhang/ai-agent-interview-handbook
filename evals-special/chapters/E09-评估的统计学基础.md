# 第 E09 章 · 评估的统计学基础

> 一句话导读：「v2 通过率 85%，比 v1 的 82% 高，可以发布」——这句话缺了三个限定词：**85% 的误差范围有多大、3 个点的差距能否与噪声区分、多大的差距才值得一次发布**。本章把评测分数装进统计学的骨架：单个分数用 Wilson 区间与 bootstrap 给出误差条；评测规模用样本量公式在跑之前算清楚；版本对比用配对设计与最小可感知变化（MPP）判定真伪；pass@k/pass^k 用无偏估计量与重复实验设计报数；竞技场排名用 Bradley-Terry、tie 建模与风格控制回归。学完本章，你能现场手算 CI 与样本量，能回答一切「这个分数可信吗」类的面试题——这也是评测岗笔试计算题的全部题源。

30 秒抓住主线：**评测是用几十到几千道题的样本，推断模型在全体任务分布上的表现——这是一个统计推断问题，不是算术问题**。于是有三个必须回答的问题：① 单个分数的误差多大（2.2–2.3）；② 多少样本才够（2.4）；③ 两个分数的差异是真是假（2.5）。在此之上，pass@k/pass^k 有自己的估计陷阱（2.6），竞技场排名自成一套配对比较统计学（2.7），而一切结论的前提是控制住噪声来源（2.8）。2024 年之前业界普遍把跑分当成确定性点估计；2024 年起，置信区间、重复实验、显著性检验成为严肃评测报告的标配——这条演进主线贯穿本章所有论文引用。

## 二、核心概念精讲

### 2.1 评测是小样本统计推断：点估计、区间估计与五大方差来源

LLM 评测的本质：**用几十到几千道题的样本，去推断模型在「全体可能任务分布」上的能力，并据此排序、做 A/B 决策**。样本有限，所以任何评测分数都是一个**统计量**（随机变量）而不是真值——换一批题、换一次运行、换一个 judge，分数都会变。2024–2026 评测统计学的主线，就是「从点估计走向分布推断」。

一个分数至少由五个随机源共同塑造（汇总自 2410.03492、2509.24086、2505.22169 的方差来源分析）：

| # | 方差来源 | 机理 | 控制手段 |
|---|---|---|---|
| 1 | 采样随机性 | temperature>0 时输出本身是抽样 | 固定温度并记录；多次 trial 取均值 |
| 2 | temperature=0 的非确定性 | 批处理效应、底层 kernel、量化的非确定性——**即使固定种子，输出仍可能不同** | 重复实验；固定并记录推理栈版本 |
| 3 | prompt 措辞敏感性 | 语义等价的改写可改变结果，即使最强模型也显著存在 | 随机化评测/prompt 扰动检验（2505.22169） |
| 4 | judge 的随机性与版本漂移 | judge 自身有噪声，升级后偏差参数会变 | judge 版本锁定；人工校准集定期重估 |
| 5 | 题目集的抽样方差 | golden set 只是任务分布的一个样本 | 报告 CI；扩容时按 1/δ² 规划 |

**推论一**：没有误差条的分数在评审中应当被质疑——这是全章最低成本、最高收益的纪律。
**推论二**：发布评测结论前，把上表过一遍，至少固定并记录其中可控项（种子、温度、judge 版本、题目集快照）。

### 2.2 通过率的置信区间：Wald 的陷阱与 Wilson score interval

通过率 p̂ = X/n（n 条用例中 X 条通过）是最基础的评测指标，也是**二项比例**。它的标准误约为 √(p(1−p)/n)——n=100、p≈0.83 时约 3.7 个点，95% 区间约 ±7.4 个点。这就是「100 条评测集上 2–3 个点的差异看不出任何东西」的数学根源。

最朴素的区间是 **Wald 区间**：p̂ ± z·√(p̂(1−p̂)/n)（95% 时 z=1.96）。公式好记，但有两个致命伤：

1. **端点越界**：n=20、全部失败（p̂=0）时，Wald 给出区间 [0, 0]——声称「真实通过率精确等于 0」，荒谬；真实上界按「三三法则」约为 3/n ≈ 15%。p̂=1 时同理给出 [1, 1]。
2. **覆盖率不足**：小样本或极端比例下，声称 95% 的 Wald 区间实际覆盖率远低于 95%，是「假安全感」。

**Wilson score interval（得分区间）是报告二项比例的默认选择**：

```text
z = 1.96（95% 置信水平）

              p̂ + z²/(2n)  ±  z·√( p̂(1−p̂)/n + z²/(4n²) )
Wilson 上下限 = ────────────────────────────────────────────
                       1 + z²/n
```

三个直觉帮你记住它：

- **它是「反转得分检验」的产物**：把所有「与观测 p̂ 不矛盾的 p₀」收集起来就是区间，构造方式天然比 Wald 的「以 p̂ 为中心对称外扩」更合理；
- **它做了收缩**：区间中心不是 p̂，而是 p̂ 向 1/2 的加权平均（权重 z²/n），n 越小收缩越强——这正是小样本需要的保守；
- **端点永远落在 [0,1] 内**，且小样本下覆盖率接近名义水平。

同一数据两种区间的对比：

| 场景 | Wald 区间 | Wilson 区间 | 评注 |
|---|---|---|---|
| n=100，85 通过 | [78.0%, 92.0%] | [76.7%, 90.7%] | 中样本下差异不大，Wilson 略宽且略向 1/2 收缩 |
| n=20，0 通过 | [0, 0]（越界/荒谬） | [0, 16.1%] | 「全挂」≠ 真通过率为 0，上界仍有 16% |
| n=20，20 通过 | [100%, 100%] | [83.9%, 100%] | 「全过」也不等于完美 |
| n=30，p̂=0.5 | ±17.9pp | ±18pp 量级 | 30 题竞赛集的分辨率只有 ~±18pp |

**覆盖率（coverage）是评判 CI 好坏的唯一硬指标**：重复做实验，区间盖住真值的频率。95% 是声明，覆盖率模拟才是验证（lab08 用固定种子模拟 1000 次，断言 Wilson 覆盖率落在 [0.92, 0.98]）。

### 2.3 Bootstrap：任意统计量的无公式误差条

Wilson 只解决「单个比例」。评测里还有中位数延迟、pass^k、BT 分数、胜率差……这些没有好用的闭式区间，通用解法是 **bootstrap**：

```text
重复 B 次（B = 500 ~ 1000）：
    从原始评测单元中【有放回】重抽样出同规模样本
    在重抽样集上重算统计量（准确率 / BT 分数 / 两模型分差 / ……）
取 B 个统计量的 2.5% 与 97.5% 分位数 → 95% CI
```

三个使用要点，全是面试追问点：

| 要点 | 说明 | 反例 |
|---|---|---|
| 重抽样单元 = 评测单元 | 成对比较按「对局」抽，分类评测按「题目」抽，多轮任务按「会话」抽 | 把一道多轮对话题拆成轮次独立重抽 → 低估方差、CI 假窄 |
| 比较两模型，bootstrap「分差」 | 对同一重抽样同时算两模型分数取差，直接看差值 CI 是否盖住 0 | 各自算 CI 再肉眼比是否重叠 → 保守且口径错误（见易错点 2） |
| B 不能太小 | B<200 时分位数本身有 Monte Carlo 误差 | B=50 的 CI 每次跑都不同，报告不可复现 |

**bootstrap vs 公式法怎么选**：二项比例优先 Wilson（稳定、无模拟误差、可复现）；任何非比例统计量、或分布假设不放心时用 bootstrap；两者都不可行（样本极少、强依赖结构）再考虑 Beta 后验等贝叶斯方法（2510.04265、2504.21303）。bootstrap 也是配对比较显著性检验的方法学源头之一（NLP 经典的配对 bootstrap 检验，Koehn 2004）。

### 2.4 样本量计算：多少题才够

评测集规模不该拍脑袋，它由「你要多高的分辨率」反解出来。分两类问题。

**问题一：估计单个通过率，要 ±ε 的精度需要多少题？**

```text
n ≥ z² · p(1−p) / ε²        （z=1.96 对应 95%；p 未知时取最坏情况 p=0.5）
```

速查表（95% 置信水平）：

| 目标半宽 ε | p=0.5（最坏情况） | p=0.8 |
|---|---|---|
| ±5pp | ~385 | ~246 |
| ±3pp | ~1,068 | ~683 |
| ±2pp | **~2,400** | ~1,537 |
| ±1pp | **~9,600** | ~6,147 |

（±2pp 需 ~2400 题、±1pp 需 ~9600 题与调研素材一致。）这解释了两个业界现象：① 把精度做细极其昂贵——从 ±2pp 到 ±1pp 样本量翻两番（**n ∝ 1/ε²**）；② 30 题的竞赛集（如 AIME 类）半宽约 ±18pp，**在统计上根本无法区分前沿模型**——业界经验法则是 **~1000 题起步才有基本功效**。

**问题二：比较两个版本，要检出 δ 的差异需要多少题？**

双比例比较（双侧 α=0.05，功效 1−β=0.8，z_β=0.84）：

```text
每组 n ≈ (z_{α/2} + z_β)² · 2·p̄(1−p̄) / δ²     （p̄ = (p₁+p₂)/2；加连续性修正再上浮 10–20%）
```

基线 80% 时的速查表（与第 E2 章门禁口径一致）：

| 想检出的差异 δ | 每组所需样本量（约） |
|---|---|
| 10pp | 250 |
| 5pp | 1,000 |
| 3pp | 2,800 |
| 1pp | ~25,000 |

**1/δ² 定律**是评测经济学的第一性原理：想检出的差异减半，评测预算翻两番。「感觉够了」通常远不够——区分两个真实胜率只差 1% 的模型，需要数千次成对比较。

**为什么 100 条 golden set 是行业常见起点**（阿里 50–200 条、Airbnb 50–100 条）？四个理由：

1. **精度匹配门禁语义**：n=100 时通过率 CI 半宽约 ±8pp，足以区分「82% vs 90% 门槛」这类大差距——门禁要的是拦截明显劣化，不是测微差；
2. **迭代速度**：100 条在分钟级跑完，支撑「一次一变量」的高频迭代（第 E10 章）；
3. **人工可审**：Airbnb 的「100 样本人工精读法」要求专家读得完每一条输出与 trace；
4. **成本可控**：agent 级评测单条成本高，100 条 × N 次重复才在预算内。

但要清楚它的边界：**n=100 只能检出 ~8pp 以上的差异**；需要分辨 3pp 就得扩到 ~2800 条（配对设计可显著更少），或接受「小提升不值得发布」的 MPP 设定（2.5）。起点与终点之间，用样本量公式显式做预算。

**先导法（把拍脑袋变成实验+公式）**：ReliableEval（2505.22169，EMNLP 2025 Findings）针对「评测对 prompt 措辞高度敏感」提出随机化评测——对一个题目生成大量语义保持的 prompt 扰动，把评测对象从单点 prompt 扩展为 prompt 分布；再用**矩方法**从先导样本估计分数方差 σ̂²，反解所需样本数：

```text
n ≥ ( z_{α/2} · σ̂ / ε )²
```

落地姿势：**先用 10% 预算跑先导集估方差，再决定全量规模**。该框架在 GPT-4o、Claude-3.7-Sonnet 等 5 个前沿模型上验证：即使最强模型也存在显著 prompt 敏感性；对高方差任务（开放生成、多轮 agent）尤其必要。

### 2.5 版本对比的显著性：配对设计与阿里门禁三件套

「v1 82%，v2 85%，v2 更好？」——先看设计，再看检验。

**配对设计优于独立设计**，原因是评测里最大的噪声源是**题目难度差异**，而不是模型差异：

| 设计 | 做法 | 噪声结构 | 检出力 |
|---|---|---|---|
| 独立设计 | v1、v2 各抽一批题分别跑 | 题目难度差异 + 模型差异混在一起 | 低：差异被题目噪声淹没 |
| **配对设计** | 两版本跑**同一批**题，逐题对比 | 题目难度被「自己当自己的对照」钉死，只剩同题上的版本差异 | 高：检出同一 δ 所需样本量显著更小 |

配对数据的标准检验是 **McNemar 检验**：把每题的两版本判定整理成 2×2 表，只看**不一致**的题——A 对 B 错（b 题）与 A 错 B 对（c 题）：

```text
χ² = (|b − c| − 1)² / (b + c)      （df=1；χ² ≥ 3.84 即 α=0.05 显著）
```

直觉：两版本都做对/都做错的题对「谁更好」毫无信息量；全部信息集中在不一致的题上。等价地，也可以对「逐题分差」做配对 bootstrap，取差值 CI 看是否盖住 0。**不要用两独立比例的 z 检验**——那是独立设计的工具，用在配对数据上既浪费信息又可能错。

**手算示例**（面试计算题常见形态）：n=100 配对，两版本都做对 70 题、A 对 B 错 8 题、A 错 B 对 14 题、都做错 8 题。裸通过率 A=78%、B=84%，「B 高 6 个点」；但 McNemar 只看翻转：χ²=(|8−14|−1)²/(8+14)=25/22≈1.14 < 3.84，**不显著**——6pp 的裸差距里，不一致样本太少、方向性不够强，证据不足以支持「B 更好」。这个例子说明配对检验的判据是**翻转样本的数量与方向比**，而不是裸分差。

**阿里门禁三件套**。阿里对版本对比的统计口径要求（原文表述）：

> 「门禁不只看差了多少，还要看差异是否超过统计噪声。」

落到纸面是三件事缺一不可：

1. **置信区间**：关键指标报告区间（比例用 Wilson，其余用 bootstrap），不报 CI 的点估计视为噪声；
2. **显著性判断**：与基线做配对检验，差异要能被证明不是抽样波动；
3. **最小可感知变化（MPP）**：提前定义「提升多少才值得发布」。统计上能检出 0.5pp，不等于 0.5pp 值得一次发布风险——MPP 把「值不值」从统计问题还原为业务决策。

**工作示例**（lab08 完整复现了这个实验）：

| 口径 | v1=82%、v2=85%、n=100 | 同样 3pp、n=2000 |
|---|---|---|
| 单版本 CI（约） | ±7.4pp，两区间大幅重叠 | ±1.6pp |
| 结论 | **不可判**：差异远小于统计噪声 | **可判**：差异超过噪声 |

同一个 3pp，样本量 20 倍之差，结论从「不能发布」变成「可以发布」。这就是门禁统计口径的意义：**不是卡流程，而是把「信不信这个差异」变成可计算的量**。

两个补充纪律：① 门禁同时看多个指标时，先指定一个主指标，其余按层级决策——m 个指标各自按 95% 单独判定，至少一项误报的概率是 1−0.95^m，会随指标数膨胀；② 显著性是「有没有差异」，MPP 是「值不值得」，两者都过才放行（见易错点 3）。

### 2.6 pass@k 与 pass^k 的统计学：估计、方差与重复实验设计

**pass@k 的无偏估计量**（HumanEval，2107.03374，OpenAI 2021）：每题采样 n 个解、c 个通过，则

```text
pass@k = 1 − C(n−c, k) / C(n, k)
```

它是「从 n 个解里无放回抽 k 个、至少一个通过」的组合概率，避免了「先抽 k 个再看是否通过」的点估计偏差。例：n=10、c=3 时，pass@1 = 0.3（与 c/n 一致），但 pass@2 = 1 − C(7,2)/C(10,2) = 53.3%——明显高于朴素的「30% × 2」。

**pass@k 点估计的统计缺陷**（2510.04265 的系统批判）：

- 每题样本数 n 常常很小（许多新 benchmark n=1~20），**n<20 时 pass@k 点估计方差极大**；
- **不同 n、不同题目难度混合下的 pass@1 完全不可比**——横向对比必须统一 n；
- 替代方案：把每题通过率 p 视为随机变量，用 **Beta 后验**（如 Beta(c+1, n−c+1)）刻画并聚合时传播不确定性，输出能力的后验分布而非单点分数；低样本设置下排序稳定性显著更好。
- 务实共识：**保留 pass@k 但必须附带 n 与 CI**（bootstrap 或 Beta 近似），或同时报告低方差的平均通过率 avg@k。

**pass^k：鲁棒性指标**。pass^k = 同一任务独立运行 k 次**全部成功**的比例（τ-bench 2406.12045 系统提出，2024）。若各次尝试独立同分布、单任务成功率 p，则 pass^k ≈ p^k——衰减速度远超直觉：

| p \ k | 1 | 3 | 5 | 8 |
|---|---|---|---|---|
| 0.95 | 95% | 85.7% | 77.4% | 66.3% |
| 0.90 | 90% | 72.9% | 59.0% | 43.0% |
| 0.80 | 80% | 51.2% | 32.8% | 16.8% |

但**不能拿 (平均 pass@1)^k 外推 pass^k**。τ-bench 的实测数字（论文摘要转述口径）：GPT-4o 在 retail 域 pass^1 ≈60%（官方榜单 60.4%），而 pass^8 ≈25%（摘要 <25%）——若按 iid 外推，0.60^8 ≈ 1.7%，与实测差出一个量级。原因有二：① 任务难度异质（部分任务几乎每次都对、部分几乎每次都错，pass^k 由「稳定会做的题」决定）；② 各次尝试正相关（同类错误反复出现）。反过来，若系统存在上下文污染、残留状态、下游限流等破坏独立性的因素，实测 pass^k 也可能更差。**结论：pass^k 必须实测，不能外推**；报告时同时给 pass@1 与 pass^k，两者的差距就是系统方差的直接度量。工程惯例 k 取 4–8，τ-bench 的 k=8 成为行业标杆。

**重复实验设计：N=3/5/8/10 怎么取舍**

| N | 典型用途 | 代价与收益 |
|---|---|---|
| 3 | 最低可行重复：筛选候选变更、CI 冒烟 | 性价比拐点：3–5 次重复 + 均值/中位数聚合能显著降低排名翻转率（2509.24086） |
| 5 | 腾讯评分规则的一致性口径（「N 次全达标取均值，建议 N=5」） | 兼顾成本与稳定性，适合日常门禁 |
| 8 | τ-bench pass^8 口径；DoorDash 全量 sweep = 50 场景 × 8 trials = 400 次对话（人工约 6 小时+，模拟器约 20 分钟） | 可靠性发布指标的标准选择 |
| 10+ | 高风险发布评估、对外论文级结论 | 边际收益递减，仅在方差估计本身要很准时用 |

两条依据：其一，**单次运行的排名翻转概率不可忽略**——在典型 benchmark 规模下，3–5 次重复 + 聚合能显著降低翻转率（2509.24086），这与 2410.03492、2504.07086 相互印证：**重复次数是评测预算里性价比最高的一项**，比重跑新 benchmark 便宜得多，却能直接消除排名噪声；其二，对 agent 这类高方差任务，预算应分配给「重复次数 + prompt 扰动」，而不是只堆新题目。内部评测平台的合理默认：`num_repeats ≥ 3`，报告均值 ± 区间。

### 2.7 竞技场方法论：Bradley-Terry、tie 建模、bootstrap CI 与风格控制

Chatbot Arena 把偏好评测从「固定 benchmark」变成「众包配对比较」，也随之引入一整组统计问题：多少投票才够？分差多少算真？平局怎么办？风格偏好算不算偏差？这套方法论由四篇工作奠基（2403.04132、2412.18407、2406.11939、2404.04475）。

**Bradley-Terry vs Elo**。对每场对局 (i, j)，BT 模型把胜率建模为潜在强度之比：

```text
P(i 胜 j) = γᵢ / (γᵢ + γⱼ)，γ > 0
```

用全部对局做极大似然估计（通常加先验/锚点约束防漂移），再换算到 Elo 尺度：`Elo_i = 400·log10(γᵢ/γ_anchor) + Elo_anchor`。而 Elo 是在线增量更新：`Elo_i ← Elo_i + K·(outcome − expected)`，期望胜率 = 1/(1+10^(−ΔR/400))。两者是**同一概率模型的两种算法**：

| 维度 | 增量 Elo | Bradley-Terry MLE |
|---|---|---|
| 计算方式 | 序贯增量，每场更新 | 离线联合极大似然 |
| 结果依赖 | **依赖对局顺序、初始分、K 因子** | 顺序无关 |
| 统计推断 | 难以给出联合 CI / 假设检验 | 可做 bootstrap CI、协方差与渐近正态推断 |
| 适用 | 实时展示 | 正式排名与比较（LMSYS、Arena-Hard、leaderbot 的选择） |

这就是 2024 年各家排行榜从 Elo 切换到 BT 的根本原因：**Elo 只是 BT 的一种粗糙在线近似**。Chatbot Arena（2403.04132，ICML 2024）论文发表时已有 240K+ 投票、180+ 模型，其最终方案就是 **BT 评分 + bootstrap 置信区间**（对投票数据有放回重抽样、重新拟合 BT、取分位数得 95% CI），BT 分数的 bootstrap CI 通常宽 **5–15 Elo 分**——媒体常把 2–5 分的差距宣称为「超越」，而这样的差距经常落在 CI 重叠区内。

**Tie 不能丢**。Arena 投票中约一成以上是平局，标准 BT 不支持 tie，三种处理方式的对比：

| 做法 | 问题 |
|---|---|
| 丢弃 tie | 浪费 ~10% 数据，且平局若非随机出现会引入偏差 |
| 各记半分（half-win） | 简单但没有概率模型支撑 |
| **tie 扩展模型**：Rao-Kupper（带优势阈值）、Davidson（P(tie) ∝ 2ν√(γᵢγⱼ)） | 有统计基础 |
| **factored tie model + 协方差估计**（2412.18407） | 显式建模「平局倾向」，并给出排名参数的协方差结构与渐近正态性——模型间分差可做正式假设检验，而不只是看 CI 是否重叠；开源实现 leaderbot |

2412.18407 是竞技场方法论从工程实践到统计学的正式化。自建竞技场/内部偏好评测平台时，这是最值得直接抄的作业：**BT MLE 替代增量 Elo；显式建模 tie；相邻排名的分差必须经联合协方差检验才能宣称显著**。

**排名有多脆弱**？两项攻击性研究给出警告：

| 研究 | 发现 | 工程对策 |
|---|---|---|
| 丢票敏感性（2508.11847） | 仅丢弃一小撮成对比较样本，顶部排名就可能改变——根源是顶部模型真实差距小 + 比较图稀疏（模型对交战不均） | 均衡比较图：对头部模型对主动加权采样（active pairing） |
| 投票操纵（2501.17858） | 用影响函数识别「翻转哪些投票对排名影响最大」，少量操纵票即可实质性提升排名 | 投票审计、异常检测、对高影响力投票复核；**排名指标不应成为唯一优化目标** |

**风格控制回归（style control）**。LLM judge 系统性偏好更长的回答，导致「把模型调啰嗦」就能刷分（verbosity hacking）。Length-Controlled AlpacaEval（2404.04475）的解法是回归去偏：

```text
偏好 vote ~ β₀ + β₁·model + β₂·length + β₃·markdown + …
```

用逻辑回归拟合偏好后，**把所有回答的长度等风格变量固定在参考值（如全体均值）时计算期望胜率**（G-computation / 回归调整思想），得到 length-controlled win rate。效果：与 Chatbot Arena 的 Spearman 相关性从 0.94 提升到 **0.98**；verbosity 操纵带来的胜率增益从约 12% 压缩到约 **3%**。Chatbot Arena 随后引入 style control（多元逻辑回归控制长度、markdown 格式等混淆变量，见 LMSYS 2024-08 博客），并同时发布 overall 与 style-controlled 两个榜单——这等于承认「风格偏好是偏差还是真实用户偏好」取决于你要回答什么问题（学界争议，见 2.8 与第 E13 章）。Arena-Hard（2406.11939，ICML 2025）的 v2 同样引入 style control，其完整配方是「竞技场分布蒸馏 + 强 judge 成对比较 + BT 分数」：从 Arena 真实投票与 WildChat 中聚类蒸馏出 500 道高区分度题目（Arena-Hard-Auto），用强模型 judge 对候选模型 vs 基座模型做成对比较，再用 **BT 把胜率升级成可比较的分数**——与 Chatbot Arena 人类排名相关性 **98.6%**，区分度约为 MT-Bench 的 **3 倍**，成本 **<$20**。这是「离线自动评测对齐在线竞技场」的模板，其「固定一个参考模型、报告 BT 分数而非裸胜率」的做法被大量内部 eval 系统模仿。

**工程结论**：任何怀疑输出表面特征（长度、格式、emoji、代码块数量）与质量混淆的 judge 评测，都应做混淆变量回归检查——方法只是一个逻辑回归，却能把抗操纵性提升一个量级。

### 2.8 噪声与可复现：方差清单、重复实验与 judge 报告规范

**「temperature=0 + 固定 seed 所以结果确定」是常见误解**。图灵研究所的实证研究（2410.03492）核心结论：即使 temperature=0 + 固定随机种子，模型输出仍可能不确定——批处理效应、底层 kernel、量化的非确定性都会让单次跑分不可复现。该工作还系统研究了重复次数、benchmark 规模、温度对分数均值与预测区间的影响，并提出低成本的分数不确定性量化方法（子集重抽样/重复实验的稀疏设计），让「给分数加误差条」不再昂贵。

**可复现性控制清单**（方差来源 → 动作）：

| 方差来源 | 控制动作 | 报告要求 |
|---|---|---|
| 采样随机性 | 固定温度并写入配置 | 报告温度与 trial 数 |
| 推理栈非确定性 | 固定并记录推理引擎/批处理配置；重复 ≥3 次 | 报告重复次数与聚合方式（均值/中位数） |
| prompt 措辞 | 关键结论做 prompt 扰动检验（2505.22169 随机化评测） | 报告扰动敏感性 |
| judge 漂移 | judge 版本锁定；升级后用人工校准集重估偏差 | 报告 judge 版本号 |
| 题目抽样 | golden set 快照化、只增不减（第 E3 / E10 章） | 报告数据集版本 |

重复实验的量化依据（2509.24086，与 2410.03492、2504.07086 互证）：**典型 benchmark 规模下，单次运行的排名翻转概率不可忽略；3–5 次重复 + 均值/中位数聚合能显著降低翻转率**。延伸阅读中，2504.07086 主张 bootstrap 多次运行取均值来评估推理模型的进步；2512.07795 提出「Run Noise」指标专门分离重复运行的随机性；2502.05234 分析温度与多次采样聚合的方差权衡。争议的本质是成本：重复 3 次意味着 3 倍推理预算，对动辄数千美元的 agent 评测尤甚——但对比「基于单次运行做出错误发布决策」的代价，这通常是最便宜的一笔保险。

**judge 评测的统计报告规范**（详见第 E5 章，此处给统计学骨架）：

```text
观测 judge 分数 = 真实分数 + judge 偏差(bias) + judge 噪声(variance)
```

How to Correctly Report LLM-as-a-Judge Evaluations（2511.21140）指出：直接报告 judge 原始准确率/胜率会混入偏差与噪声，不同 judge 的分数不可直接比较；应使用**偏差校正估计量**——用一个小规模人工标注校准集（几百条）估计 judge 的混淆结构/偏差，对被评模型的真实胜率做校正，并构造 CI。judge 升级/换型后偏差参数需重估；多 judge 面板的收益取决于 judge 间**错误相关性**（相关错误不随面板规模下降）。同时记住理论下界（2410.13341，ICLR 2025）：**在前沿任务上 judge 评测的误差随样本量下降存在理论极限，靠 judge 做评测最多相当于「把人类标注数据翻倍」的收益量级**——judge 适合扩大覆盖，不能替代高质量人工校准集；前沿模型的评测必须保留人工锚点（第 E6 章）。阿里口径与此一致：judge 与人工复核一致率约 85%（参考值）后才进日常自动化，且每次 judge 升级固定产出「与人工一致性 / 高风险漏判率 / 边界样本稳定性」三项统计。

**报告纪律汇总**（评测报告的最小检查表）：

1. 一切分数带 CI：二项比例用 Wilson；成对胜率/排名用 bootstrap（按评测单元重抽样，B≥500）；
2. 版本比较用配对设计（McNemar 或配对 bootstrap），不用两个独立点估计的肉眼对比；
3. pass@k 必须报 n，统一各模型的采样预算；题目少时用 Beta 后验区间；
4. 重复 ≥3 次，报告均值 ± 区间；temperature=0 + seed 也要重复；
5. 样本量在评测前用公式/先导实验规划，而不是跑完再看；
6. 竞技场式排名用 BT MLE + tie 模型 + 均衡比较图 + style control；
7. judge 分数报告偏差校正后的值与 CI，附 judge 版本与校准集状态；
8. CI 重叠的排名视为统计上不可区分，向业务方给「不可区分组」而非精确名次。

**面试计算速查表**（第四节计算题的公式都在这里）：

| 问题 | 公式 |
|---|---|
| 通过率 CI | Wilson：(p̂ + z²/2n ± z√(p̂(1−p̂)/n + z²/4n²)) / (1 + z²/n) |
| 估计精度所需样本 | n ≥ z²·p(1−p)/ε² |
| 两版本比较样本 | 每组 n ≈ (z_{α/2}+z_β)²·2p̄(1−p̄)/δ² |
| 先导法反解样本 | n ≥ (z_{α/2}·σ̂/ε)²（ReliableEval 2505.22169） |
| 配对检验 | McNemar：χ² = (\|b−c\|−1)²/(b+c) |
| pass@k 无偏估计 | 1 − C(n−c, k)/C(n, k)（2107.03374） |
| pass^k（iid） | ≈ p^k（不可用平均值外推，须实测） |
| BT→Elo | Elo_i = 400·log10(γᵢ/γ_anchor) + Elo_anchor |

## 四、经典面试题与参考答案

#### 题 1（基础）：什么是置信区间？为什么评测通过率推荐 Wilson 区间而不是 p̂±1.96·SE？

**参考答案：** 通过率 p̂=X/n 是从有限评测集算出的统计量，会随抽样波动；置信区间给出「真实通过率大概率落在的范围」——95% CI 的含义是：重复做实验，约 95% 的区间会盖住真值。朴素的 Wald 区间 p̂±1.96·√(p̂(1−p̂)/n) 有两个致命伤：① 端点越界——n=20 全失败时给出 [0,0]，声称真通过率精确为 0，而其实际上界按三三法则约 3/n≈15%；② 小样本/极端比例下实际覆盖率远低于名义 95%，制造假安全感。Wilson 区间是得分检验的反转：中心把 p̂ 向 1/2 收缩（权重 z²/n，n 越小收缩越强），端点永远落在 [0,1]，小样本覆盖率接近名义水平。所以报告二项比例一律用 Wilson；只有大样本、p̂ 远离 0/1 时两者才近似一致。

#### 题 2（基础 · 计算）：Golden set 100 条，通过 85 条。给出通过率的 95% Wilson 置信区间，并解释它对版本对比意味着什么。

**参考答案：** 代公式：z²=3.84，中心 =(0.85+0.0192)/(1.0384)≈0.837，半宽 =1.96·√(0.001275+0.000096)/1.0384≈0.070，得 **[76.7%, 90.7%]**（Wald 会给出 [78.0%, 92.0%]，略窄且位置偏高）。含义有三：① 真实通过率可能低至 ~77%——点估计 85% 附近 ±8 个点都与数据相容；② 若发布门槛是 90%，区间上端刚触线、下端差很远，**不能宣称达标**，需要扩样本或改进系统；③ 若另一版本跑出 82%，其 CI 约 [73.3%, 88.3%]，两区间大幅重叠——3 个点的差距在 n=100 下不可判，要做配对检验或直接扩到千级样本。这道题的口算关键：n=100、p≈0.8 时标准误约 4 个点，95% 半宽约 8 个点，记住这个量级就能快速应对一切变体。

#### 题 3（基础）：temperature=0 且固定了随机种子，评测结果就完全可复现了吗？为什么仍要多次重复？

**参考答案：** 不是。随机源至少有三层：① 采样随机性（temperature>0）——这一层确实被 temperature=0 消除；② 推理栈的非确定性——批处理效应、底层 kernel、量化数值误差会让同样的输入在不同 batch 组成/并发顺序下得到不同输出，图灵研究所的实证（2410.03492）确认即使 temperature=0+固定种子，单次跑分仍可能不可复现；③ 评测环境层——工具返回漂移、上下文组装差异（第 E8 章 fixtures 解决的就是这个）。所以重复实验不可省：2509.24086 显示典型 benchmark 规模下单次运行的排名翻转概率不可忽略，3–5 次重复 + 均值/中位数聚合能显著降低翻转率。工程默认：固定并记录种子与推理栈版本、`num_repeats≥3`、报告均值 ± 区间——重复次数是评测预算里性价比最高的一项。

#### 题 4（进阶 · 计算）：基线通过率 80%，想检出新版 prompt 的 5pp 提升（α=0.05 双侧，功效 0.8）。需要多大的评测集？如果预算只够 300 条，怎么办？

**参考答案：** 双比例样本量公式：每组 n ≈ (z_{α/2}+z_β)²·2p̄(1−p̄)/δ²，其中 p̄=(0.80+0.85)/2=0.825，(1.96+0.84)²≈7.85，得 n≈7.85×2×0.825×0.175/0.0025≈907，加连续性修正约 **1000 条/版本**（与第 E2 章门禁口径的速查表一致）。预算只有 300 条时四个选项：① **配对设计**——两版本跑同一批 300 题，用 McNemar 检验，题目难度被钉死后检出力显著提高，300 条在差异较大（如 ≥8pp）时可用；② **提高 MPP**——把「值得发布的门槛」从 5pp 放宽到 ~10pp（n≈250 即可检出），接受小提升不上线；③ **先导法**（ReliableEval 2505.22169）——先用 ~30 条先导集估方差，确认真实方差比二项假设小再定规模；④ 诚实地向业务方报告：300 条的分辨率就是 ±5pp 量级，小于此的差异「测不出来」而不是「没有」。核心态度：样本量是评测前算出来的，不是跑完后后悔出来的。

#### 题 5（进阶）：评测报告显示 v1 82%、v2 85%（n=100），PM 说「提升了 3 个点，发布吧」。你怎么回应？

**参考答案：** 三步。第一步，定量拒绝：n=100、p≈0.83 时标准误约 3.7pp，95% CI 半宽约 ±7.4pp，两版本区间大幅重叠——3pp 完全在统计噪声内，当前数据不支持「v2 更好」。第二步，给正确方法：让 v1、v2 跑**同一批** 100 题做配对比较，用 McNemar 检验只看判定翻转的题；若翻转样本中 v2 赢的显著多于 v1 输的才算有信号。第三步，给决策框架（阿里门禁三件套）：即使统计显著，还要过**最小可感知变化（MPP）**——如果业务上 3pp 不值得一次发布风险，就事先把 MPP 定为 5pp；要可靠检出 3pp 需约 2800 条/组（配对可更少），把「扩评测集到千级」或「接受小提升不发布」两个成本显式摆出来。一句话：**门禁不只看差了多少，还要看差异是否超过统计噪声**（阿里），这个案例的答案是「现在不能发，数据不够」。

#### 题 6（进阶）：pass@k 和 pass^k 有什么区别？为什么 pass^k 不能用 (pass@1)^k 外推？τ-bench 的数字说明了什么？

**参考答案：** pass@k = k 次尝试**至少一次**成功，度量能力上限；pass^k = k 次**全部**成功，度量生产可靠性——用户不会接受「多试几次总有一次成」，支付/退款类场景必须看后者。pass@k 要报无偏估计量 1−C(n−c,k)/C(n,k)（HumanEval，2107.03374），并附每题采样数 n——n<20 时点估计方差极大，不同 n 的结果不可比（2510.04265）。pass^k 在「独立同分布」假设下 ≈ p^k（p=0.9、k=8 时只剩 43%），但真实系统不能用平均值外推：τ-bench（2406.12045）实测 GPT-4o retail 域 pass^1≈60%、pass^8≈25%，而 0.60^8≈1.7%——差一个量级，因为任务难度异质（会做的题每次都做对）且各次尝试相关。反方向上，上下文污染、残留状态、限流也会破坏独立性。所以 pass^k 必须实测：工程惯例 k 取 4–8，重复 N 的取舍是 3 次起步筛选、5 次日常门禁（腾讯口径）、8 次发布级可靠性（τ-bench / DoorDash sweep 口径）。

#### 题 7（进阶）：为什么 Chatbot Arena 用 Bradley-Terry 而不是 Elo？平局（tie）应该怎么处理？相邻两名分差 4 分能宣称「超越」吗？

**参考答案：** 两者是同一概率模型 P(i≻j)=γᵢ/(γᵢ+γⱼ) 的两种算法：Elo 是在线增量近似，结果**依赖对局顺序、初始分与 K 因子**，只适合实时展示；BT 是全部对局的联合极大似然，顺序无关，且能做统计推断——这是 LMSYS 从增量 Elo 切到 BT+bootstrap CI 的根本原因（2403.04132，ICML 2024）。Tie 不能丢也不能简单记半分：Arena 投票中约一成以上是平局，丢弃浪费数据且若非随机会引入偏差，半分无概率模型支撑；正确做法是用 tie 扩展模型（Davidson：P(tie)∝2ν√(γᵢγⱼ)；或 2412.18407 的 factored tie model，还给排名参数估计协方差，支持正式假设检验；开源 leaderbot）。4 分的分差：Arena 的 BT bootstrap CI 通常宽 5–15 Elo，4 分大概率落在重叠区——**CI 重叠的相邻排名应视为统计上不可区分**，对外应报告「不可区分组」；2508.11847 还显示丢弃一小撮对局就可能翻转顶部排名，所以结论要同时看 CI 与比较图覆盖是否均衡。

#### 题 8（进阶）：自动评测器被「长答案」刷分了——模型输出越来越啰嗦，分数水涨船高。如何诊断与治理？

**参考答案：** 这是 verbosity hacking，本质是 judge 的长度偏好被当成了质量信号。诊断：① 画「judge 分数 vs 输出长度」散点/分桶图，看相关性；② 抽样人工复核长答案，确认长度增益是否对应真实质量；③ 对比同一批回答在长度截断前后的胜率变化。治理的标准解法是**风格控制回归**（Length-Controlled AlpacaEval，2404.04475）：用逻辑回归拟合 偏好 ~ β₀+β₁·model+β₂·length+β₃·markdown+…，然后把长度固定在参考值（如全体均值）计算期望胜率——即 length-controlled win rate（G-computation 思想）。效果量化：AlpacaEval 与 Chatbot Arena 的 Spearman 相关性从 0.94 升到 0.98，verbosity 操纵的胜率增益从 ~12% 压到 ~3%。工程上：任何 judge 指标都应做混淆变量回归检查（长度、格式、emoji、代码块），至少并行发布风格控制后的口径；Arena-Hard v2（2406.11939）也把 style control 作为标配与 Arena 的 style-controlled 排名对齐。注意争议面：风格偏好也可能是真实用户体验的一部分，所以 LMSYS 同时发布 overall 与 style-controlled 两榜——指标必须声明自己的语义。

#### 题 9（系统设计）：为一个客服 agent 设计一套统计上严谨的评测与发布门禁。现有 100 条 golden set、一个 LLM judge、每次全量评测预算有限。

**参考答案：** 分五层设计。**① 估计与报数**：通过率一律 Wilson CI；非比例指标（延迟分位数、成本）用 bootstrap（B≥500，按会话重抽样）；judge 分数先经人工校准集做偏差校正再报（2511.21140），judge 与人工一致率达到公司口径（如阿里 ~85%）才进自动化。**② 重复设计**：每条用例跑 N 次——日常迭代 N=3~5（成本与翻转率折中），发布评估 N=8（τ-bench/DoorDash 口径）；报告 pass@1 与 pass^k 双指标，pass^k 实测不外推；不可逆操作（退款）类场景 pass^k + P0 风险样本 0 失败。**③ 样本量规划**：100 条的分辨率是 ±8pp，只够门禁拦截大退化；要检出 5pp 的版本差异，用配对设计（同题集 + McNemar）把需求压低，或扩集到 ~1000 条（1/δ² 定律：3pp 需 ~2800 条/组）；扩集前先跑 10% 先导集估方差（ReliableEval 矩方法）。**④ 门禁决策规则**（阿里三件套）：P0 硬约束（风险样本 0 失败）先过 → P1 统计比较：配对检验显著 + 差异 CI 不盖 0 + 超过事先定义的 MPP → 放行；多指标时指定主指标防多重比较膨胀。**⑤ 运营纪律**：judge 版本锁定、升级重校准；golden set 快照化只增不减；重复次数、种子、数据集版本全部写入报告；离线门禁通过后仍要线上灰度联动（第 E12 章）。预算有限时的优先级：重复次数 > 配对设计 > 扩题数——重复是性价比最高的一项（2509.24086）。

## 五、易错点 · 反直觉点

1. **误区：temperature=0 + 固定 seed，跑分就完全确定了。** 真相：批处理效应、底层 kernel、量化的非确定性仍在，单次跑分照样不可复现（2410.03492 实证）。**记忆锚点：固定种子≠固定输出，重复实验是最后一道防线。**
2. **误区：两个模型的 CI 不重叠才算显著，重叠就是不显著。** 真相：比较两个独立 CI 的重叠是既保守又口径错误的近似；正确做法是配对设计后直接 bootstrap「分差」看是否盖住 0，或用 2412.18407 的联合协方差检验。**记忆锚点：判分差自己的 CI，别拿两个区间比重叠。**
3. **误区：统计显著 = 值得发布。** 真相：样本够大时 0.3pp 的差异也能显著，但可能完全不值得一次发布风险；阿里门禁要求显著性与**最小可感知变化（MPP）**同时满足。**记忆锚点：显著性回答「有没有差」，MPP 回答「值不值得」。**
4. **误区：平局（tie）可以丢弃或各记半分。** 真相：Arena 投票中 tie 占一成以上，丢弃浪费数据且非随机缺失时引入偏差，半分没有概率模型支撑；应使用 Davidson/Rao-Kupper 或 factored tie 模型（2412.18407）。**记忆锚点：每十票就有一票平局，丢 tie 等于篡改数据。**
5. **误区：pass@k 直接跨模型、跨 benchmark 比较。** 真相：pass@k 的方差强烈依赖每题采样数 n，n<20 时点估计基本不可信，不同 n 的结果完全不可比（2510.04265）；必须统一 n 并附 CI。**记忆锚点：不带 n 的 pass@k 是裸奔的分数。**
6. **误区：30 题的竞赛集能区分前沿模型。** 真相：n=30、p=0.5 时 95% CI 半宽约 ±18pp，这个分辨率下两个模型的分数差异几乎都在噪声内；业界经验是 ~1000 题起步才有基本功效。**记忆锚点：30 题的尺子，刻度是 ±18 个点。**
7. **误区：pass^k ≈ (平均 pass@1)^k，可以外推。** 真相：任务难度异质 + 尝试间相关让实测 pass^k 与 iid 外推差出一个量级——τ-bench 实测 61%→25%（k=8），而 0.61^8≈2%。pass^k 必须实测。**记忆锚点：p^k 是物理课的公式，pass^k 是实验课的测量。**
8. **误区：增量 Elo 是模型的最终实力分。** 真相：增量 Elo 依赖对局顺序、初始分与 K 因子，只是 BT 的粗糙在线近似；正式排名用 BT 联合 MLE + bootstrap CI，这也是 LMSYS 切换的原因（2403.04132）。**记忆锚点：Elo 看顺序，BT 看全局。**
9. **误区：judge 的原始分数可以跨模型、跨版本直接比较。** 真相：观测 judge 分数 = 真实分数 + 偏差 + 噪声，不同 judge 口径不同；必须用人工校准集估计偏差、报告校正后的分数与 CI（2511.21140），judge 升级后偏差参数重估。**记忆锚点：judge 分数是仪表读数，先校准仪表再读数。**
10. **误区：跑一次就够了，重复实验是浪费预算。** 真相：单次运行的排名翻转概率不可忽略，3–5 次重复 + 聚合能显著降低翻转率（2509.24086）；重复比重建新题集便宜得多。**记忆锚点：重复 3 次，是最便宜的严谨。**
