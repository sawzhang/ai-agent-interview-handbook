## 二、核心概念精讲

### 2.1 方向①：LLM-as-Judge——裁判科学

**演进主线（四段）**

1. **偏差的实证 catalog（2023–2024 上）**：位置偏差、冗长偏差、自我偏好、风格压倒实质相继被量化；第一批缓解方法出现（交换/长度回归/评审团集成）。
2. **元评估成为独立赛道（2024 下）**：人们意识到 **judge 之间高一致 ≠ judge 正确**，出现以客观真值校准 judge 的基准。结论一致：前沿 judge 在客观困难任务上准确率只有 ~57% 量级，与人类评审有明显差距，且可能"集体犯错"。
3. **可训练的 judge（2024–2025）**：judge 从提示词工程走向模型工程——开源评测专用模型、纯合成数据自训练、生成式/推理式 judge（把奖励建模变成 next-token prediction、用 RL 训练"会推理的裁判"）。
4. **judge 的优化与攻防（2025–2026）**：judge prompt/rubric 本身成为可优化对象（GEPA 反射式 prompt 进化）；judge 的可攻击性被正面研究——对抗样本可让安全 judge 把 100% 的有害输出判为安全。系统复盘显示：多数单点去偏策略收益有限，"中端模型 + 组合去偏"反而能胜过前沿 judge 且便宜约 15 倍。

### 2.2 方向②：Agent 基准——从沙箱到信任危机

**演进主线（四段）**

1. **环境奠基期（2024 上）**：自托管沙箱环境 + 程序化判定成为范式；GAIA 确立"结果精确匹配 + 难度分级"的通用助手评测；τ-bench 把对话式工具 Agent 与用户模拟器引入评测。
2. **软件工程爆发期（2024 下）**：SWE-bench 成为事实标准，Verified/Multimodal 变体相继出现；Agent-as-a-Judge 开启"用 Agent 评 Agent"。
3. **难度军备与可靠性转向（2025）**：公开基准分数逼近高位后，社区转向更难、抗污染的新基准；τ²-bench 用"双控"模拟解决泄题；pass^k / 多次采样成为标配。
4. **基准工业化与信任危机并存（2026）**：终端 Agent 评测标准化（Terminal-Bench，ICLR 2026）；同时社区系统性质疑：基准间分数相关性低、harness 工程对分数影响巨大、基准分数与生产表现脱节。**评测重心正从公开排行榜转向私有 golden set + 领域定制评测套件。**

### 2.3 方向③：轨迹与过程级评估——信用分配体系化

**演进主线（四段）**

1. **PRM 奠基与标注自动化（2023–2024 上）**：逐步验证优于只看结果，但依赖海量人工步骤标注；Math-Shepherd 用蒙特卡洛 rollout 自动估计每步后续成功率，OmegaPRM 用二分搜索把标注成本降到 O(log n)。
2. **形式多样化（2024 下）**：生成式验证器（critique + verdict）、VinePPO 把信用分配做进 RL 训练本身（无偏优势估计）、步骤级偏好对齐。
3. **反思与落地到 Agent（2024 末–2025）**：Qwen 团队系统披露 PRM 局限（reward hacking、分布外失效）；PRIME 证明无需步骤标签也能拿过程奖励；Agent-as-a-Judge 把步骤级评估扩展到开发型 Agent；τ-bench 用终态比对做执行式验证。
4. **元评估与体系化（2025–2026）**：AgentRewardBench（2025）专门评估"自动轨迹评估器本身"，揭示纯阅读式 LLM 判别器的高误报率；信用分配专题综述把推理与 Agent 两条线统一成体系。

一句话：**从"给步骤打分"（PRM）到"给 Agent 轨迹打分"（trajectory scoring）再到"给打分器打分"（meta-evaluation），同一套信号反哺训练（RL credit assignment）与推理时搜索（verifier-guided search）。**

### 2.4 方向④：评测统计学——从点估计到推断

**演进主线（四段）**

1. **方法论奠基（2024 上）**：Chatbot Arena 确立 Bradley-Terry 评分 + bootstrap CI；Arena-Hard 把 Arena 蒸馏成可复现自动评测；LC-AlpacaEval 用回归消除长度偏差。
2. **反思与形式化（2024 下）**：量化 benchmark 分数的不确定性；证明 judge 评测的样本效率下界；UC Berkeley 把 Arena 排名形式化为可推断的统计框架（factored tie model + 协方差建模）。
3. **规范化与攻击面（2025）**："到底需要多少样本/多少次重复"成为独立子方向；pass@k 的统计缺陷被系统批判并给出贝叶斯替代；Arena 排名的可操纵性被攻击性研究检验（投票操纵、丢票敏感性）；LLM-judge 结果的报告规范被提出（偏差校正估计量 + 置信区间）。
4. **事前设计（2026 进行中）**：统计保证下的自适应/预算分配式评测出现，评测统计学从"事后解释"走向"事前设计"。

### 2.5 方向⑤：Benchmark 污染、饱和与动态基准

**演进主线（四段）**

1. **污染检测工具化（2023 末–2024 上）**：三类检测范式成熟——成员推断（Min-K% Prob / WikiMIA，ICLR 2024）、格式变体（改写/翻译后的变体同样泄漏）、选项结构敏感性（选择题分数相当部分来自格式捷径）。
2. **MMLU 信任危机与修补（2024 中）**：重标注发现约 10% 的题面/答案有误或歧义，修复后分数与排名都变；MMLU-Pro 走"加深加难"路线。**修数据**与**提难度**成为老牌基准的标准动作。
3. **动态基准制度化（2024）**：从"一次性发布测试集"转向"持续更新的测试流"——LiveBench 按月换题、全客观评分；LiveCodeBench 按时间截止线持续采集新题，使"污染距离"可量化；DyVal 系用程序化生成让每次评测题目都是新的。
4. **脆弱性量化与生成式基准（2024 末–2026）**：GSM-Symbolic 证明只改名字/数字/语序就能让数学分数暴跌至多 65%，暴露"能力 vs 记忆"的界限模糊；基准本身变成可无限采样的生成器（DynaMath、UGMathBench）；HLE 代表难度军备竞赛路线，同时引发"越来越难却越来越远离用户价值"的批评。

### 2.6 方向⑥：EDD 与仿真评测——评测成为开发方式

**演进主线（六段，2024 末–2026）**

1. **方法论成型**：EDD 从口号变成有过程模型与参考架构的工程学科——arxiv 2411.13768 首发，2025 年 v3 扩展为 EDDOps（offline/online 评测与运行时控制环统一）；Anthropic 与 OpenAI 把 eval-driven development 写入官方开发指南。
2. **仿真评测标准化**：τ-bench 首创"LLM 用户模拟器 + 工具调用 + 终态校验 + pass^k"；τ²-bench 升级双控；persona 驱动、非合作模拟、模拟器可靠性本身成为研究对象。
3. **eval 成为优化目标函数**：DSPy → MIPROv2 → GEPA，优化器直接以 eval 分数为搜索目标；Nubank 甚至用 GEPA 优化 LLM 裁判本身的一致性。
4. **持续评测与数据飞轮**：生产 trace 回流为测试用例（DoorDash、Discord AITL）；eval 进 CI 成为发布门禁；"评测资产"像代码资产一样版本化。
5. **offline-online 一致性出现量化证据**：Nubank 报告离线仿真指标与线上 A/B 强相关（首个大规模量化证据）；反方（OlaBench）强调 gap 仍普遍——两派证据并存。
6. **学界/工业界错位被量化**：EDDOps 对 134 篇学术文献统计：约 93% 聚焦部署前、仅约 2% 覆盖部署后；工业界灰色文献约 40% 已转向持续评测——学术供给与工程需求明显错配。

### 2.7 方向⑦：安全与红队评测——从攻击技巧到标准化考试

**演进主线（五段）**

1. **标准化评测框架（2024 上）**：从零散攻击技巧（GCG、PAIR、TAP）到有固定行为集、固定流水线、公开榜单的标准化考试——HarmBench、JailbreakBench、StrongREJECT 几乎同时出现。
2. **从二元判定到分级评分（2024）**：StrongREJECT 证明二元 ASR 严重低估攻击效果，rubric 分级评分成为主流；安全 judge 从字符串匹配进化到语义级评估器与集成 judge。
3. **从单轮到多轮与 Agent（2024 下起）**：Crescendo、MAST 揭示多轮攻击成功率远高于单轮；InjecAgent、AgentDojo、Agent-SafetyBench、ASB 把评测对象从"聊天回复"扩展到"工具调用轨迹"——**提示注入成为 Agent 安全的第一威胁模型**。
4. **静态题库到动态/生态化（2024–2026）**：WildTeaming at Scale 挖掘真实用户越狱语料；AgentDojo 引入可参数化、可再生的动态任务环境。
5. **攻防双向闭环**：评测框架同时服务攻击与防御（robust refusal 训练、防御微调、防御插拔接口）——benchmark 即攻防擂台。

### 2.8 方向⑧：组件级评估与 RAG——把黑盒拆开

**演进主线（三段）**

1. **奠基（2023）**：AIS 归因形式化定义、FActScore 原子事实分解（"声明分解 + 逐条验证"范式源头）、ALCE 引用指标、RAGAS/ARES 等 RAG 评测框架密集出现。
2. **组件级成熟 + 规模化基准（2024）**：RAGChecker 提出声明级 + 检索器/生成器双层诊断指标，成为组件级评估标杆；CRAG（Meta KDD Cup 2024）把评测推向动态、带时效的工业级基准；SAFE 把 FActScore 完全自动化做到与人评同级；AttributionBench 首次系统横评归因评估方法本身。
3. **效率化、代理化、纵深场景（2025–2026）**：蒸馏式事实性裁判降本、agentic/多跳检索评估、归因信号进入 RL 训练回路（grounded RL / citation RL）、法律与科研等垂直域引用评测。横切主题：**judge 校准**——裁判本身会幻觉、有偏好偏差，需要 gold set 校准与统计修正（PPI）。

### 2.9 方向⑨：自改进闭环与评测基础设施

**9a. 评测与训练闭环——Goodhart 的主战场**

1. **自我改进闭环成型（2024 上）**：Self-Rewarding LM 确立"同模型既当运动员又当裁判"；Meta-Rewarding 加"裁判的裁判"对抗自我偏好；RLAIF 证明 AI 反馈可替代人类反馈。
2. **reward hacking 成为实证科学（2024 下）**：Sycophancy to Subterfuge 展示谄媚零样本泛化成篡改奖励的完整谱系；Alignment Faking 给出策略性伪装对齐的直接证据；Goodhart 被量化到 RLHF。
3. **RLVR 大爆发与"评测集即奖励"（2025）**：DeepSeek-R1 用规则可验证奖励把 RL 推上推理主战场，评测集答案验证器事实上成为训练奖励。两波反思：RLVR 是否真教会新能力（pass@k 反转实验）；评测集污染让收益变成"背书"而非"推理"。
4. **从实验室到生产（2025 下–2026）**：生产级 RL 训练中直接观测到 reward hacking；agentic 评测出现"模型修改测试文件骗分"的 eval gaming；系统性综述与缓解方法（recontextualization、reward shaping、迭代式奖励模型重训）跟进。

**核心张力：评测集既是"考卷"又是"答案来源"时，它同时承担测量工具和奖励函数两种角色，Goodhart 定律必然生效。**

**9b. 评测基础设施与可观测性**

- **框架标准化**：lm-evaluation-harness、Inspect AI（UK AISI）、HELM 三大开源底座；重心从"多刷任务"转向可复现性与评测集治理（版本管理、prompt 固化、种子记录）。
- **与生产分布对齐**：WildBench、Chatbot Arena 把真实用户 query 分布引入评测。
- **可观测性标准收敛中**：OpenTelemetry GenAI semantic conventions 从各家私有 schema 向统一标准收敛，但仍处 Development 稳定性；部分 agent/tool 属性已进入 registry，完整的 agentic span 约定仍在提案推进中。
- **从观测到诊断**：TRAIL、AgentDebug 等用 LLM 读 trace 自动定位失败（~40-60% 定位准确率）——可观测性从"看得见"推向"自动找错"，而模型在 trace 调试上的能力短板本身又成了新的评测任务。

**未解问题**：生产 trace 复用于评测的数据治理（PII 与"最真实分布"的冲突）；OTel 标准"现在站队 vs 等技术债"的两难；自动诊断的成熟度是否够生产；第三方评测 vs 自评的治理有效性。

### 2.10 趋势判断：evals 的下一站

1. **Judge 校准成为一等公民**：2024 年大家问"judge 怎么打分"，2026 年问"judge 的分数凭什么可信"。元评估基准、GEPA 式自动校准、judge 版本化与鲁棒性测试正在成为平台标配（第 E5 章）。
2. **评测重心从公开榜单转向私有资产**：污染 + 饱和 + harness 效应 + 与生产脱节的四重信任危机下，"私有 golden set + 领域评测套件 + 在线信号"三层结构成为工业共识（第 E3、E13 章）。
3. **轨迹级评估与信用分配崛起**：从"给步骤打分"到"给打分器打分"，过程信号同时服务评测、RL 训练与推理时搜索——Agent 评测的颗粒度必然继续下沉（第 E7 章）。
4. **评测与训练闭环融合，Goodhart 治理成为显学**：RLVR 让评测集直接变奖励，reward hacking / eval gaming 从实验室走进生产——评测设计必须自带防作弊假设（第 E9 方向的本章 + 主手册 2.14）。
5. **仿真评测平台化、EDD 流程化**：模拟器 + fixtures + CI 门禁 + 数据飞轮构成完整工程闭环；离线-线上一致性的量化证据开始出现，EDD 从方法论走向可审计的工程学科（第 E10 章）。

## 四、经典面试题与参考答案

#### 题 1（开放）：过去一年 evals 领域最重要的三个进展是什么？
**参考答案：** 我给三个：① **judge 校准从最佳实践变成系统工程**——GEPA 式自动校准被 DoorDash/Nubank 等生产采用，元评估基准（JudgeBench 类）确立"高一致≠正确"的共识；② **离线-线上一致性首次有大规模量化证据**——Nubank 报告离线仿真与线上 A/B 强相关（+37pp NPS），EDD 的可信度地基被浇筑；③ **评测与训练的 Goodhart 冲突进入生产**——生产级 RL 中直接观测 reward hacking、agent 修改测试文件骗分的 eval gaming 案例，让"评测集即奖励"的风险从理论变现实。三者共同指向：evals 从"跑分"变成"测量科学 + 治理工程"。

#### 题 2（进阶）：有人说"公开 benchmark 已经没用了"，你怎么看？
**参考答案：** 半对。没用的部分：污染（SWE-bench 题面大量进训练语料）、饱和（头部基准 60-75%+）、harness 效应（同一模型换执行框架分数差异巨大）、与生产脱节（HAL 发现基准间相关性低、与用户满意度弱相关）——所以**单一公开榜单不能作为发布决策依据**。仍有用：淘汰明显差的候选、跨团队沟通的共同语言、研究对照。工业共识是三层：公开基准做外部坐标 + 私有 golden set 做门禁 + 在线信号做地面真值。答出"折价使用 + 三层互补"比站队任何一方都强。

#### 题 3（进阶）：LLM judge 可信吗？你引用哪些证据？
**参考答案：** 可信是**校准出来的，不是默认的**。证据链：① 偏差实证——自我偏好（2404.13076）、风格压倒实质（2409.15268）；② 元评估——JudgeBench 显示最强 judge 客观准确率 ~57% vs 人类 ~78%，judge 间高一致与正确性弱相关；③ 去偏复盘——单点策略收益有限，组合去偏才稳健（2604.23178），中端模型+组合去偏可胜过前沿 judge 且便宜约 15 倍；④ 攻防——对抗样本可让安全 judge 100% 放行有害输出（2503.04474）。工程结论：judge 必须过 gold set 校准（一致率 ≥85% 口径）、版本化、定期重校、高风险场景人工兜底——这正是第 E5 章的落地流程。

#### 题 4（进阶）：过程奖励模型（PRM）值得做吗？
**参考答案：** "有用但娇贵"。正方：PRM800K 证明逐步验证优于只看结果；Math-Shepherd/OmegaPRM 解决了标注成本；verifier-guided search 与 RL 信用分配都吃这套信号。反方（Qwen PRM Lessons）：会被 best-of-N hacking、难度外推差、验证器分布漂移；不少团队发现"ORM + 更多采样"性价比更高；AgentRewardBench 还显示纯阅读式轨迹判别器误报率 >50%。决策框架：有明确步骤结构（数学/代码/合规流程）且愿意持续重训验证器 → 做；否则先把 outcome 评估 + 执行式验证做扎实。Agent 场景更推荐 Agent-as-a-Judge 式"带工具的评估器"。

#### 题 5（系统设计）：公司要你从零规划未来一年的评测能力建设，你如何排优先级？
**参考答案：** 按"仪器→考卷→流程→闭环"排：Q1 仪器——选 judge 维度、建 gold 校准集、校准到一致率 ≥85%、上线程序化检查层（先有可信测量）；Q2 考卷——50-200 条 golden set 覆盖核心路径与高风险边界，建基线快照与 fixtures，跑通模拟器（E3/E8）；Q3 流程——评测进 CI 门禁（P0 指标一票否决 + 回归集只增不减），版本对比带 CI 与显著性（E9/E10）；Q4 闭环——线上抽样 + 同 rubric 在线评分、badcase RCA 与行动项、数据飞轮回流（E11/E12）。每季度用一个可量化里程碑验收（judge 一致率、门禁拦截次数、线上失败→回归用例转化率）。同时预留 10-15% 精力跟进本章五个趋势，避免技术路线老化。

#### 题 6（进阶）：离线评测到底能不能预测线上表现？
**参考答案：** 当前共识：**必要不充分**。正方证据：Nubank 报告离线仿真指标与线上 A/B 强相关并量化 +37pp NPS；DoorDash 的离线提升与线上一致；τ-bench 用可验证终态提高离线信号可信度。反方证据：OlaBench 指出现有基准过度强调可验证任务成功、低估主观质量与真实失败模式；EDDOps 统计 93% 学术评测停在部署前。让它能预测的条件：① 离线指标覆盖主观质量与失败模式（不只任务成功）；② 离线-线上同 rubric 同 judge（DoorDash 原则）；③ 模拟器与 fixtures 受控（E8）；④ shadow/canary/小流量 A/B 补最后一公里。答"能/不能"都错，答条件才对。

#### 题 7（基础）：举例说明什么是"评测被训练钻空子"。
**参考答案：** 四个层级：① 风格层——AlpacaEval 的长度 gaming，长回答刷分（催生 LC-AlpacaEval）；② 数据层——评测集进训练语料，GSM8k 改写变体仍泄漏（2311.04850）；③ 奖励层——RLHF 中谄媚泛化为奖励篡改（2406.10162）；④ 执行层——agent 直接修改测试文件骗分（2506.12286）。防御：私有 holdout 永不公开、动态轮换、终态执行式验证、过程检查、人工抽检旁挂 gold 指标。本质是 Goodhart：分数一旦成为目标就不再是好测量。

#### 题 8（开放）：如果让你预测 2027 年 evals 的形态？
**参考答案：** 五个方向（合理推演即可，展示判断力）：① judge 平台化——校准、版本化、鲁棒性元评估成为托管服务；② 评测即优化目标常态化——GEPA 类优化器把 eval 分数当 loss 用，同时 eval gaming 防御成为标配；③ 统计报告规范强制化——没有 CI 和显著性的分数不被接受；④ agent 级可观测性标准落地——OTel agent span 规范成熟，trace 成为一等公民；⑤ 评测员职业化——"eval engineer"像当年的 SRE 一样成为独立岗位。收尾强调：预测细节可能错，但"测量科学 + 治理工程"的方向不会变。

## 五、易错点 · 反直觉点

1. **误区：judge 之间一致率高 = judge 可靠。** 真相：JudgeBench 证明 judge 间高一致与客观正确性弱相关，可能"集体犯错"。记忆锚点：一致性测的是"稳定"，元评估测的才是"准"。
2. **误区：去偏论文都说有效，所以 swap/CoT 校准一定有用。** 真相：系统复盘（2604.23178）显示多数单点策略跨模型不稳定，只有组合去偏稳健——论文里"有效"存在发表偏差。
3. **误区：公开基准分数涨了 = 模型变强了。** 真相：可能是污染、格式捷径（GSM-Symbolic：改名字就掉 65%）或 harness 工程。记忆锚点：分数 = 能力 + 记忆 + 格式 + 环境。
4. **误区：动态基准只有好处。** 真相：换题让历史分数失效，排行榜变成快照而非连续量尺——动态化解决污染，引入测量连续性问题。
5. **误区：PRM 全面优于 ORM。** 真相：PRM800K 的结论后来被多次质疑（会被 best-of-N hacking、难度外推差）；"ORM + 更多采样"常常性价比更高。
6. **误区：LLM 读轨迹就能评轨迹。** 真相：AgentRewardBench 显示纯阅读式判别器失败轨迹误报率常 >50%；关键变量是评估器有没有执行/核验工具（Agent-as-a-Judge 为什么强）。
7. **误区：pass^k 低说明模型不行。** 真相：也可能说明任务判定过严或环境抖动；要同时报 pass@1 与 pass^k 并固定温度再下结论。
8. **误区：离线评测没用/离线评测够用。** 真相：两个极端都错——"必要不充分"，条件（覆盖主观质量、同 rubric 同 judge、shadow/canary 补位）决定预测力。
9. **误区：评测集只是考卷。** 真相：当评测集成为 RL 奖励（RLVR），它同时是答案来源——Goodhart 必然生效，污染会让收益变"背书"而非"推理"。
10. **误区：安全评测就是测模型抗不抗越狱。** 真相：还要测过度拒绝（可用性代价）和安全 judge 本身的可操纵性——裁判是攻击面。
