# Evals 特辑写作规范（所有写作智能体必读）

## 项目背景
本特辑位于 `evals-special/`（主仓库根目录下），是主手册（AI Agent 面试学习手册）的
**评估（evals）专题深度卷**。主手册第 8 章是面试浓缩版；本特辑是全景深挖版，目标是
"把 evals 体系讲透彻"：知识体系 + 可运行实验 + 2024-2026 前沿论文调研。

## 语言与基调
- 全部简体中文；论文/产品/指标名保留英文原文（如 LLM-as-a-Judge、pass^k、τ-bench）。
- 读者画像：资深工程师、正在搭建评测体系的团队、面试候选人。
- 基调：工程实战导向，每个概念都要落到"怎么做、怎么算、怎么判"。拒绝空洞口号。
- 内容基准日：2026-08。涉及前沿论文时标注 arxiv ID 与年份。

## 章节固定 6 模块结构（必须严格遵守，标题措辞一致）
```markdown
# 第 E<N> 章 · <标题>

> 一句话导读（本章解决什么问题、学完能得到什么）

## 一、知识图谱
用 ASCII 图 / 结构化表格 / 分层列表呈现本章知识骨架（让读者 30 秒建立全景）。

## 二、核心概念精讲
### 2.1 ...
### 2.2 ...
（主体内容。多用表格对比、代码块、数字、真实案例。小节数 4~8 个）

## 三、面试高频考点
表格或列表，每条带 ⭐ 分级（⭐基础必备 / ⭐⭐进阶高频 / ⭐⭐⭐系统设计或深水区），
并给一句话考察意图。8~14 条。

## 四、经典面试题与参考答案
#### 题 1（基础/进阶/系统设计）：<题目>
**参考答案：**（结构化、有层次、有数字/例子；长度 150~400 字）
每章 6~10 题，覆盖基础→进阶→系统设计梯度。

## 五、易错点 · 反直觉点
编号列表，每条：误区描述 → 真相 → 一句话记忆锚点。6~10 条。

## 六、推荐资源
论文（arxiv 链接）、工程博客、开源工具、相关章节/labs 交叉引用。
```

## 交叉引用约定
- 引用本特辑其他章节：`（详见第 E5 章 · LLM-as-Judge 深入）`
- 引用主手册：`（主手册第 8 章 · Agent 评估与可观测性）`
- 引用 labs：`labs/eval_labNN_xxx.py`，运行命令写 `cd evals-special/labs && python3 eval_labNN_xxx.py`

## 质量红线
1. **事实准确**：论文引用必须来自 `_research/` 调研报告（已核实 arxiv ID）；不要凭记忆编造论文标题/数字。
2. **数字要具体**：凡是工业实践（Airbnb/DoorDash/阿里/腾讯），优先引用 `_research/00-industry-practice.md` 里的原始数字。
3. **避免与主手册第 8 章简单重复**：本章是深挖，可以重新组织但要显著更深（更多机制细节、数字、案例、前沿论文）。
4. 每章正文 450~900 行 markdown（不含空行可略少），宁深勿水。
5. 表格优先于长段落；对比类内容必须用表格。
