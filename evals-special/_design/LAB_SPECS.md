# Evals 特辑 Labs 规格书（LAB_SPECS）

写 lab 的智能体必读。所有 lab 位于 `evals-special/labs/`（主仓库根目录下的相对路径）。

## 硬性约定（与主仓库 labs/ 一致，不可违背）
1. **纯 Python 标准库、零第三方依赖**。只允许：json、re、random、statistics、math、time、
   dataclasses、typing、collections、itertools、functools、hashlib、copy、enum 等标准库。
2. **确定性**：所有随机行为 `random.seed(...)` 固定种子；同一输入永远同一输出；
   assert 在任何机器上都能通过。
3. **文件结构**：
   - 顶部中文 docstring：【实验目的】【对应章节】【核心概念】【如何运行】【思考题（面试延伸）】
   - 中部：分节实现（用 `# --- N. 标题 ---` 分节 + 大量中文注释解释原理）
   - 末尾：`# --- 自检 ---` 区，一组 assert + 汇总打印
   - 最后一行输出：`print("✅ 自检通过：<lab 名> 全部断言成立")`
4. **Mock LLM/Judge** 若需要：实现 `chat()`/`__call__` 接口，与主仓库 `labs/llm_client.py` 的
   QwenLLM 同构，可互换。Mock 的行为逻辑要能体现本实验要演示的现象（如注入位置偏差）。
5. **可独立运行**：`cd evals-special/labs && python3 eval_labNN_xxx.py`，退出码 0。
6. **代码规模**：300~700 行（含注释）。注释讲"为什么"，不是复述代码。
7. **自检要有牙齿**：assert 必须断言本实验的核心结论（例如"缓解后偏差显著缩小"），
   不能只断言"程序跑完了"。
8. 写完后必须亲自运行 `python3 <文件>` 验证通过，失败就修到过。

## 共享小工具
若多个 lab 需要相同工具（如 tokenize/overlap），各自内联实现（保持零依赖、可独立运行），
不要建共享模块（与主仓库风格一致：每个 lab 自包含）。

## Lab 清单

### eval_lab01_metric_system.py — 指标体系：pass@k / pass^k / 一致性
- 实现 pass@k（k 次至少 1 次成功）与 pass^k（k 次全部成功）的估计函数（无偏估计公式与朴素估计对比）。
- 模拟 N 个任务 × K 次重复运行的 agent 结果矩阵（固定种子），演示：
  至少一次成功率（能力上限）与连续成功率（生产要求）的差距随 K 增大而拉开。
- 演示"用户不接受多试几次总有一次成功"：给一个单任务成功率 p=0.8 的 agent，
  计算 pass^1..pass^8 并断言单调下降。
- 对比两类 Agent（关键决策类 vs 创意类）在不同容忍阈值下的"可发布"结论差异。
- 核心断言：pass^k ≤ pass@k；pass^k = p^k（独立同分布假设下）数值吻合；阈值判定逻辑正确。

### eval_lab02_golden_dataset.py — 黄金数据集构建与治理流水线
- 定义用例结构（dataclass）：id/来源/场景/输入/期望行为/风险等级/状态（能力集/回归集/已毕业）。
- 演示四类来源的构造：专家用例（手写）；LLM 扩展（MockLLM 基于结构字段生成同场景变体，
  验证"先定结构字段再生成自然语言"）；badcase 回流（把一条线上失败入库为新用例）。
- 实现"毕业"机制：用例连续 M 个版本通过率 100% → 从能力集转入回归集；回归集只增不减。
- 实现入库标准检查器（可复现/期望明确/根因标签/代表性/已脱敏——用字段存在性模拟）。
- 核心断言：扩展用例保留结构字段；毕业流转正确；不满足入库标准的 badcase 被拒。

### eval_lab03_programmatic_scorers.py — 程序化评分与分层筛查
- 实现规则评分器家族：JSON schema 校验、空/异常长度检测、关键词黑白名单、
  工具调用断言（是否调用指定工具、参数正确性）、执行指标（调用次数上限、耗时预算）。
- 评分输出规范：每个 scorer 返回 {score, pass/fail, 问题分类, 置信度, 判定依据}。
- 实现两层流水线：粗筛层（便宜规则）→ 精判层（昂贵规则）；粗筛明确失败的样本不再进精判。
- 构造样本集：明显失败（JSON 损坏）/边界样本/通过样本，验证分层路由与成本节省（统计精判调用次数）。
- 核心断言：坏样本在粗筛被拦截且给出正确问题分类；成本节省 > 阈值。

### eval_lab04_judge_bias.py — Judge 偏差量化与缓解
- MockJudge：真实质量信号 + 可注入的三种偏差：位置偏差（偏好第一个）、冗长偏差（偏好更长）、
  自我偏好（偏好与自己"同风格"的输出，用字符串风格标记模拟）。
- 实验 1：无偏 judge 基线（A/B 真实质量差 → 胜率反映真实差距）。
- 实验 2：注入位置偏差后，同等质量下 A 放第一位的胜率显著 > 50%。
- 缓解 1：交换顺序取平均（swap-and-average）→ 偏差收敛到 ~0。
- 缓解 2：三 judge 投票 → 偏差进一步受控。
- 缓解 3（冗长偏差）：长度受控评分（对长度分桶内比较）或惩罚项。
- 核心断言：偏差量化数字、缓解前后对比（缓解后 |偏差| < 缓解前 × 0.3 之类有牙齿的阈值）。

### eval_lab05_judge_calibration.py — Judge 校准闭环（一致率 / kappa / 迭代）
- 构造 60 条 gold 集：样本 + 人工标签（good/bad），其中故意包含"正确的改述"
  （好答案但与参考答案字面不同）与"流畅的错误"（坏样本）。
- Judge v1：字面重叠式 rubric → 一致率 ~75-80%，会误罚正确改述（复现 Airbnb 案例）。
- 实现混淆矩阵、一致率（agreement）、Cohen's kappa、按错误类型分解的分歧分析。
- 校准循环：分析分歧样本 → 修订 rubric（放宽改述惩罚、加事实核对项）→ Judge v2 → 一致率 ≥85%。
- 演示"judge 升级后重新校准"：rubric 变更后 kappa 监控三项（一致性/高风险漏判率/边界稳定性）。
- 核心断言：v1 一致率 < 0.82，v2 ≥ 0.85，kappa 同步提升；v1 在改述样本上误判数 > 0 而 v2 显著减少。

### eval_lab06_trajectory_eval.py — 轨迹三层评估与假阳性捕获
- 定义 Trace 结构：spans = [{type: tool_call/tool_result/message, name, params, result, ts, parent}]。
- 三层评分器：
  step-level（工具参数 schema 校验、禁用动作检查）、
  trajectory-level（工具调用序列与基线 LCS 对齐 + 归一化：时间戳占位、忽略查询参数；
  不一致/多余/缺少/顺序错各扣分）、
  session-level（最终目标是否达成 + 关键信息是否覆盖）。
- 构造四类 agent 运行：完全正确 / 结果对但路径错（跳过了关键校验工具——假阳性）/
  路径对但结果错 / 全错。验证过程评分能抓住"结果对但路径错"（outcome-only 评分会漏掉）。
- 核心断言：假阳性样本 outcome 分高但 trajectory 分低 → 综合判定失败；LCS 对齐扣分符合预期。

### eval_lab07_simulator_fixtures.py — 会话模拟器与 Fixtures
- MockLLM 扮演顾客：scenario 定义开场请求/用户目标/反应策略（状态机驱动：
  未解决且有进展→继续；被反问→补充信息；连续 2 次无进展→升级投诉）。
- Fixtures：工具调用被拦截并返回录制好的 payload（如订单历史 v1），任何运行都看到同样外部状态。
- 同一 scenario 运行 N 次（seed 固定），验证产物可复现、评分稳定。
- 对照组：不用 fixture（用"漂移的"伪实时数据）→ 评分方差变大，说明"环境不受控时分数测量的是噪声"。
- 实现一个简版 rubric 检查清单（checklist 式：目标商品在清单里/总价≤预算/无编造商品）。
- 核心断言：fixture 组 N 次评分一致；漂移组方差显著更大；checklist 能抓住超预算场景。

### eval_lab08_statistics_ci.py — 评测统计学：置信区间 / 样本量 / 显著性
- Wilson score interval 实现 + 与朴素 Wald 区间对比（小样本下 Wald 越界问题）。
- Bootstrap 置信区间实现（固定种子重采样）。
- 样本量计算器：给定基线 p、想检出的最小差异 δ、显著性水平，返回所需样本数（公式实现+速查表打印）。
- 版本对比：两版本各 N 样本配对比较 → 差异 + CI + "是否超过统计噪声"判断；
  演示 3% 差异在 N=100 下不可判、N=2000 下可判（对应阿里门禁统计口径）。
- 核心断言：CI 覆盖率（用固定种子模拟 1000 次实验，95% CI 覆盖真值比例 ∈ [0.92, 0.98]）；
  样本量函数单调性；配对检验结论与预期一致。

### eval_lab09_rca_pipeline.py — Badcase 根因分析流水线
- 实现 RCA 五步：证据汇总（按 session_id 聚合 trace 日志）→ 范围收敛
  （"问题现象 × 功能模块"映射表：答非所问→[意图识别,Query改写,知识筛选]；
  事实性错误→[FAQ检索,知识检索,回复生成]；过度承诺→[风险拦截,回复生成]）→
  分模块诊断（逐模块读 IO，输出 PASS/SOFT_PASS/FAIL）→ 责任判定（三层：严重 FAIL 直接定责 →
  规则模式匹配 → LLM 兜底（MockLLM））→ 结构化落盘（dict：问题分类/现象/枚举/责任模块/置信度/修复建议）。
- 内置 3-4 个 badcase（含"已发货退款未查订单状态"阿里案例）验证定责正确。
- 实现聚类：同根因/同场景 badcase 聚成问题簇，输出"场景 X 中 N 次跳过校验，集中在 vY Prompt"。
- 核心断言：每个 badcase 的责任模块与预设一致；聚类输出数量正确。

### eval_lab10_edd_loop.py — EDD 全闭环：门禁 / 回归 / 一次一变量
- 模拟一个 GenAI 功能的评测驱动开发循环：
  ① golden set（含坏样本）+ P0 门禁（通过率 ≥90% 且 0 个 P0 风险样本失败）；
  ② 候选变更队列：prompt_v1（基线）/ prompt_v2（修 A 类错误）/ prompt_v3（修 B 但改坏旧场景——回归陷阱）
  / model_swap（换模型）；
  ③ 每次只评一个变更（一次一变量纪律的断言：变更队列里每个条目只改一个维度）；
  ④ 回归检测：新版本必须同时通过新增用例与既有回归集；prompt_v3 应被门禁拒绝；
  ⑤ badcase 回流：被拒绝版本暴露的新失败模式 → 编码为新用例进入回归集（只增不减）。
- MockLLM 作为被测系统：行为由 (prompt 版本, 模型) 决定，内置几类错误模式。
- 核心断言：v2 通过门禁且旧用例不回归；v3 被拒绝；回归集大小单调不减；最终版本全绿。

### eval_lab11_arena_bradley_terry.py — 竞技场：Bradley-Terry / Elo / 风格控制
- 实现成对比较数据生成器：潜在质量分 + 注入位置偏差与长度偏好。
- Bradley-Terry 极大似然估计（迭代算法，纯标准库实现）恢复模型强度排序。
- Elo 评分系统实现（含 K 因子），与 BT 结果对照。
- Bootstrap 强度差的置信区间 → "两模型差距是否显著"。
- 风格控制演示：加入长度作为混杂变量后，朴素 BT 把"长"误判为"强"；
  长度分桶/回归残差法（简化实现）修正后恢复真实排序。
- 核心断言：无偏数据下 BT 排序与真实质量排序一致（Kendall τ=1 或 Spearman 检验）；
  有偏数据下朴素排序出错、修正后恢复。
